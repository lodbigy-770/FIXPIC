# PLAN – תוכנת Windows מקומית להסרת אובייקטים מתמונות (Big LaMa, CPU, Offline)

> סטטוס: מסמך חי. עודכן לאחרונה: 2026-11-12. מצב השלבים ב-`ROADMAP.md` (לוח מצב) וב-`PROGRESS.md`.
> מוסכמה: כל טענה על המודל מסומנת **[אומת]** (נבדקה בפועל) או **[לא אומת]** (הנחה / ידע כללי שטרם נבדק מול הקבצים בפועל).

## 1. חזון ומטרות

**העתק חוויה של Cleanup.pictures, במצב Offline גמור**, כתוכנת Windows מקומית: מסמנים במברשת, ה-AI מסיר מיד, ממשיכים למשיכה הבאה. הסרת אנשים, חפצים, טקסטים ופגמים באמצעות AI Inpainting (Big LaMa).

מפרט הפריטיות המלא (מה נכנס, מה לא, ומקורות המידע) נמצא ב-`PARITY-SPEC.md`. שם גם מוגדרת לולאת החוויה (משיכה → עיבוד מיידי → תוצאה), שהיא ההנחה המעצבת של הארכיטקטורה.

**יתרון על הגרסה המקוונת:** ללא העלאה לשרת, ללא מגבלת רזולוציה, ללא סימן מים וללא חשבון. **פער ידוע:** אין "refiner" מקצועי, והאיכות היא של Big LaMa בלבד.

- עבודה מלאה Offline לאחר ההתקנה.
- שמירה על רזולוציית התמונה המקורית (הפלט באותו גודל פיקסלים כמו הקלט).
- ביצועים סבירים במחשב רגיל, ללא GPU.
- אפס תלות בענן, ב-CUDA או ב-GPU.

## 3. דרישות לא פונקציונליות

- **Offline**: אפס קריאות רשת בזמן ריצה. המודל נארז עם ההתקנה. אין טלמטריה, עדכון אוטומטי או רישוי מקוון.
- **Latency (קריטי לחוויה):** הלולאה "משיכה → תוצאה" דורשת Inference לכל משיכה. **תקציב Latency (הוכרע 2026-11-12, נמדד על i5-6500T עם 4 ליבות, כלומר מקרה גרוע יחסית; זמני Inference ב-4 threads):** אינטראקטיבי: קלט למודל עד 256 (כ-0.8 שניות); רגיל (ברירת מחדל): עד 384 (כ-2 שניות); איכות: עד 512 (כ-4 שניות, הפעלה ידנית); כבד: 768 ומעלה (10 שניות ומעלה), רק ידני עם חיווי התקדמות וביטול. ROI גדול מקלט המודל מוקטן (Resize זול) ומורץ ב-512 לכל היותר, ממוזג בחזרה במסכה בלבד. השפעת ההקטנה על האיכות תיבדק ב-M2. פירוט: `DEVELOPMENT_LOG.md` (2026-11-12).
- **חוויית עבודה:** ממשק לא נחסם בזמן עיבוד; שמירת פרופורציות, תצוגה חלקה ב-Zoom/Pan.
- **שפה:** עברית בלבד (RTL), החלטה ראשונית. טקסטים בקובצי משאבים כדי לאפשר הוספת שפה בעתיד.
- **עברית בנתיבי קבצים:** תמונות בתיקיות ובשמות קבצים בעברית חייבות להיטען ולהישמר תקין (ראו ARCHITECTURE §5).
- **אפליקציה עצמאית:** תוכנת Windows מקומית; ללא דפדפן, WebView2 או Electron. התקנה עצמאית שאינה דורשת התקנת Python או רכיבים מהרשת (Python נארז בתוך החבילה).
- **חומרה**: Windows 10/11, 16GB RAM, CPU בלבד.
- **זיכרון**: תקרת זיכרון מוגדרת (יעד ראשוני: מתחת ל-4GB לשיא ריצה על תמונה של 24MP – **יעד, לא נמדד**).
- **דיוק מקורי**: פיקסלים מחוץ למסכה נשארים זהים לבייט למקור (מיזוג חוזר רק בתוך המסכה + Feathering).
- **יציבות**: שגיאה בהרצה לא מפילה את האפליקציה ולא פוגעת בתמונה הנוכחית.
- **תחזוקה**: פתרונות פשוטים, מקומיים; מודל ניתן להחלפה ללא שינוי בשאר המערכת.
- **רישוי**: בדיקת רישיון לכל רכיב לפני הכללתו במוצר מסחרי.

## 4. מגבלות חומרה

- ללא GPU: כל החישוב על ה-CPU, ב-OpenVINO (ראשי) או ב-ONNX Runtime CPU Execution Provider (fallback). ראו ADR-011.
- זמן ההרצה צפוי להיות תלוי בגודל הקלט ובמספר הליבות. **[לא נמדד]** – ימדד ב-Milestone 1.
- הסביבה שבה נערך התכנון (סנדבוקס, 1 ליבה, ~3GB RAM) **אינה** מייצגת את סביבת היעד; מדידות ביצועים רשמיות ייעשו על חומרת יעד.

## 5. שלבי הפיתוח

ראו `ROADMAP.md` לפירוט מלא. תקציר:

0. קליטת מודל ומחקר (שלבים 1–2 במסמך המשימה) – **בוצע ואושר** (KIRO, הורץ אצל המשתמש)

4. Milestone 4 – Advanced Editing
5. Milestone 5 – Production

### שלב ביניים מוצע (M1.5 – Latency Spike והחלטת Runtime/Stack)
בין M1 ל-M2: מדידת זמן Inference לכל משיכה (ROI קטן/בינוני/בגודל קלט מלא) ב-ONNX Runtime CPU, השוואה ל-OpenVINO, ובדיקה אם יש צוואר בקבוק מחוץ ל-Inference (עיבוד, UI, זמן עלייה) שמצדיק העברת רכיב לקוד נייטיב. התוצאה קובעת את תקציב ה-Latency הסופי. ההחלטה מתועדת ב-`ARCHITECTURE.md` (ADR).

## 6. קריטריוני הצלחה

1. המודל נטען ב-ONNX Runtime CPU ומפיק תוצאה תקינה ויזואלית על בדיקת PoC.
2. פלט זהה במידות לקלט, ופיקסלים מחוץ למסכה לא השתנו.
2א. כל יכולות P0 ב-`PARITY-SPEC.md` ממומשות ועוברות בדיקה ידנית מקצה לקצה.
2ב. השוואה צד-לצד מול Cleanup.pictures על סט תמונות ייחוס (הסרת אדם, טקסט, שריטה): התוצאה "קרובה במידה סבירה"; הפערים מתועדים בכנות (אין הנחה שהאיכות זהה).
3. תמונה של לפחות 12MP מעובדת בלי קריסה ובלי חריגה מתקרת הזיכרון.
4. כל המערכת עובדת בלי חיבור לאינטרנט (נבדק עם ניתוק רשת).
5. Undo/Redo עובד לפחות 20 צעדים על תמונה בינונית.
6. מתקין שאינו דורש אינטרנט ואינו דורש הרשאות מפתח.
