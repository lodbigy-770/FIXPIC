## שלב 0 – קליטת מודל ומחקר (קדם-תנאי ל-M1)

**תלות:** הורדת המודל ע"י המשתמש (אין גישה ל-Hugging Face מסביבת העבודה).

**סטטוס (2026-11-11):** בוצע בעיקרו ע"י KIRO (קומיטים `9923eb3`, `94d3064`): נבנתה חבילת `stage0_validation/` עם נקודת כניסה `validate_stage0.py`, וההרצה נעשתה אצל המשתמש על הקובץ האמיתי. **אושר ע"י פלט ההרצה שהמשתמש הדביק** (קוד יציאה 0, SHA256 וגודל תואמים, לא pointer, session נטען; פרטים ב-`DEVELOPMENT_LOG.md`). בסביבת Claude הקובץ נשאר LFS pointer (הרשת חוסמת את `github-cloud.githubusercontent.com`), ולכן ההרצה לא שוחזרה כאן. הטווח 64–4096 עדיין לא אומת.

**מטרות:** להכניס את קבצי המודל לריפו ולאפיין אותו על בסיס הקבצים בפועל.

**משימות**
- [ ] בדיקת מבנה הריפו ב-HF; זיהוי קובץ ה-ONNX וקבצי עזר (config, metadata, external data).
- [x] הורדת קבצים נחוצים בלבד אל `models/big-lama/` (ONNX דרך LFS, README, LICENSE).
- [ ] תיעוד: Revision/Commit, שמות, גדלים, SHA256, רישיון (`models/big-lama/README.md`).
- [x] בדיקת Git LFS ואימות שאין קבצי pointer (`FileValidator`; הורצה אצל המשתמש, KIRO2).
- [x] אפיון שמות, תפקידים ומידות של Input/Mask/Output Tensors (`ModelInspector`; הורץ אצל המשתמש).
- [ ] אפיון Padding, נרמול וזיכרון בפועל (נשאר ל-M1).
- [x] עדכון `MODEL_CARD.md` על ידי `ModelCardUpdater` (סעיפים 1, 2, 3 ורשימת המשימות; גיבוי ב-`MODEL_CARD.md.bak`). סעיפים 4–6 עדיין [README] ויאומתו ב-M1.

**תוצרים:** `models/big-lama/*`, `MODEL_CARD.md` מלא.
**בדיקות:** SHA256 תואם; `onnxruntime.InferenceSession` נטען; גודל קובץ תואם לצפוי.
**DoD:** כל הנתונים ב-MODEL_CARD מסומנים "אומת" או "הנחה" באופן מפורש; אין קבצי LFS pointer.

## Milestone 1 – Model Integration

**מטרות:** להוכיח שהמודל רץ ב-CPU ומפיק תוצאה תקינה.

**סטטוס (2026-11-11):** הכלי `tools/m1/m1_check.py` ומדריך `M1-RUNBOOK.md` מוכנים. `verify`, `probe` ו-`run` הסינתטי (3 מקרים, 640×480) הורצו אצל המשתמש על Big LaMa ועברו כולם. **M1 לא סגור:** נשארו דוגמאות אמיתיות, בדיקת גודל שאינו כפולה של 8 (הריפוד טרם נבדק על המודל האמיתי) ודירוג ויזואלי. לכלי יצירת מסכות: `tools/m1/make_mask.py`.
**נדחה (2026-11-11):** המשתמש לא הצליח ליצור 3 תמונות דוגמה עם מסכות, ולכן שלב 6–8 ב-`M1-RUNBOOK.md` (דוגמאות אמיתיות, מדידת threads ודירוג ויזואלי) נדחים. אפשר להריץ בינתיים `verify`, `probe` ו-`run --out m1_out` (3 מקרים סינתטיים בלי קבצי קלט). משימות הבדיקה ההגיונית והויזואלית ב-M1 לא ייסגרו לפני דוגמאות אמיתיות.

**משימות**
- [x] טעינת Big LaMa ב-ONNX Runtime CPU (`probe`: 2.51 שניות, `CPUExecutionProvider`, onnxruntime 1.31.1).
- [x] הדפסת מטא-דאטה של Inputs/Outputs (בוצע ע"י `m1_check.py probe`, כל הבדיקות PASS; `tools/poc/probe_and_run.py` לא הורץ).
- [x] בדיקת תמונת קלט + מסכה → תמונת פלט (סינתטי בלבד, 640×480).
- [ ] אותה בדיקה על תמונות אמיתיות וגם על גודל שאינו כפולה של 8 (כדי לבדוק ריפוד).
- [x] בדיקת תקינות: גודל פלט, טווח ערכים, פיקסלים מחוץ למסכה אחרי מיזוג (סינתטי, 640×480; הפלט הגולמי מחוץ למסכה זהה למקור ב-0 רמות).
- [x] מדידת זמן וזיכרון בסיסית (640×480, ברירת מחדל של threads: כ-5.1–5.8 שניות, שיא זיכרון כ-950MB; מפרט המחשב ב-`m1_results.json` טרם נשלח).

**תוצרים:** PoC עובד, תוצאות מדידה ב-`DEVELOPMENT_LOG.md`, השלמת `MODEL_CARD.md`.
**בדיקות:** 3 תמונות בדיקה (הסרת אדם / טקסט / שריטה) – בדיקה ויזואלית; בדיקה אוטומטית שפיקסלים מחוץ למסכה זהים למקור.
**DoD:** PoC רץ מקצה לקצה ב-CPU בלי GPU וללא רשת; התוצאה תועדה.

## Milestone 1.5 (שלב ביניים) – Latency Spike והחלטת Runtime/Stack

**תלות:** M1.
**מטרות:** לבדוק אם לולאת "משיכה → תוצאה" ריאלית ב-CPU, ולהכריע ADR-002.

**משימות**
- [ ] **Latency Spike:** מדידת זמן Inference עבור ROI קטן / בינוני / בגודל קלט מלא; גם Warm (ריצה שנייה ואילך) וגם Cold.
- [ ] מדידת התלות במספר ה-Threads (1/2/4/8/כל הליבות הפיזיות).
- [ ] השוואת ONNX Runtime CPU ל-OpenVINO (אם החומרה Intel).
- [ ] מדידת עלות Pre/Post בנפרד מה-Inference.
- [ ] קביעת תקציב Latency סופי למשיכה טיפוסית (מעדכן `PLAN.md` ו-`PARITY-SPEC.md` §3).
- [ ] אימות Python: זמן Pre/Post ב-NumPy/OpenCV על ROI, זמן עלייה של האפליקציה, ושחרור ה-GIL בזמן `run` (ה-UI נשאר רספונסיבי).
- [ ] UI Spike: Zoom/Pan חלק על תמונה של 24MP ב-PySide6 (פירמידת הקטנות/Tiles לתצוגה).
- [ ] הכרעה אם נדרש רכיב נייטיב (Cython/C++) מחוץ ל-Inference.

**תוצרים:** טבלת מדידות, ADR מעודכן, תקציב Latency מוסכם.
**DoD:** החלטה מתועדת עם נתונים. אם ה-Latency גבוה מכדי חוויה אינטראקטיבית – מתועדות חלופות (OpenVINO, Quantization, ROI קטן יותר, מצב "הרץ" ידני) לפני המשך.
