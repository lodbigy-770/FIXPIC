# ROADMAP – שלבי פיתוח

> עודכן: 2026-11-10. לכל שלב: מטרות, משימות, תוצרים, בדיקות, Definition of Done (DoD).

## שלב 0 – קליטת מודל ומחקר (קדם-תנאי ל-M1)

**תלות:** הורדת המודל ע"י המשתמש (אין גישה ל-Hugging Face מסביבת העבודה).

**מטרות:** להכניס את קבצי המודל לריפו ולאפיין אותו על בסיס הקבצים בפועל.

**משימות**
- [ ] בדיקת מבנה הריפו ב-HF; זיהוי קובץ ה-ONNX וקבצי עזר (config, metadata, external data).
- [ ] הורדת קבצים נחוצים בלבד אל `models/big-lama/`.
- [ ] תיעוד: Revision/Commit, שמות, גדלים, SHA256, רישיון (`models/big-lama/README.md`).
- [ ] בדיקת Git LFS ואימות שאין קבצי pointer.
- [ ] שלב 2: אפיון Input/Mask/Output Tensors, טווח מידות, Padding, נרמול, זיכרון.
- [ ] כתיבת `MODEL_CARD.md` על סמך נתונים מאומתים.

**תוצרים:** `models/big-lama/*`, `MODEL_CARD.md` מלא.
**בדיקות:** SHA256 תואם; `onnxruntime.InferenceSession` נטען; גודל קובץ תואם לצפוי.
**DoD:** כל הנתונים ב-MODEL_CARD מסומנים "אומת" או "הנחה" באופן מפורש; אין קבצי LFS pointer.

## Milestone 1 – Model Integration

**מטרות:** להוכיח שהמודל רץ ב-CPU ומפיק תוצאה תקינה.

**משימות**
- [ ] טעינת Big LaMa ב-ONNX Runtime CPU.
- [ ] הרצת `tools/poc/probe_and_run.py` – הדפסת מטא-דאטה של Inputs/Outputs.
- [ ] בדיקת תמונת קלט + מסכה → תמונת פלט.
- [ ] בדיקת תקינות: גודל פלט, טווח ערכים, פיקסלים מחוץ למסכה אחרי מיזוג.
- [ ] מדידת זמן וזיכרון בסיסית.

**תוצרים:** PoC עובד, תוצאות מדידה ב-`DEVELOPMENT_LOG.md`, השלמת `MODEL_CARD.md`.
**בדיקות:** 3 תמונות בדיקה (הסרת אדם / טקסט / שריטה) – בדיקה ויזואלית; בדיקה אוטומטית שפיקסלים מחוץ למסכה זהים למקור.
**DoD:** PoC רץ מקצה לקצה ב-CPU בלי GPU וללא רשת; התוצאה תועדה.

## Milestone 1.5 (שלב ביניים) – Latency Spike והחלטת Runtime/Stack

**תלות:** M1.
**מטרות:** לבדוק אם לולאת "משיכה → תוצאה" ריאלית ב-CPU, ולהכריע ADR-002.

**משימות**
- [ ] **Latency Spike:** מדידת זמן Inference עבור ROI קטן / בינוני / בגודל קלט מלא; גם Warm (ריצה שנייה ואילך) וגם Cold.
- [ ] מדידת התלות במספר ה-Threads (1/2/4/8/כל הליבות הפיזיות).
- [ ] השוואת ONNX Runtime CPU ל-OpenVINO (אם החומרה Intel).
- [ ] מדידת עלות Pre/Post בנפרד מה-Inference.
- [ ] קביעת תקציב Latency סופי למשיכה טיפוסית (מעדכן `PLAN.md` ו-`PARITY-SPEC.md` §3).
- [ ] בחירת C# בלבד או ליבת C++.

**תוצרים:** טבלת מדידות, ADR מעודכן, תקציב Latency מוסכם.
**DoD:** החלטה מתועדת עם נתונים. אם ה-Latency גבוה מכדי חוויה אינטראקטיבית – מתועדות חלופות (OpenVINO, Quantization, ROI קטן יותר, מצב "הרץ" ידני) לפני המשך.

## Milestone 2 – Core Inpainting Engine

**תלות:** M1 (ו-M1.5).
**מטרות:** מנוע עצמאי (ספרייה ללא UI).

**משימות**
- [ ] `IInpaintModel` + מימוש ONNX.
- [ ] Model Manager (טעינה, מטא-דאטה, בדיקת hash).
- [ ] Pipeline: ROI, Pad/Resize, Pre/Post, מיזוג.
- [ ] Tiling עם חפיפה לתמונות/מסכות גדולות.
- [ ] ניהול זיכרון: שימוש חוזר בבאפרים, תקרה, התאוששות מ-OOM.
- [ ] ביטול (`CancellationToken`) ודיווח התקדמות.
- [ ] Job Scheduler: תור FIFO (עד 3), Worker יחיד, Warm-up של ה-Session (ARCHITECTURE §4א).
- [ ] הרחבת מסכה אוטומטית (ADR-008) ו-"רזולוציה מקורית תחילה" (ARCHITECTURE §4ב).
- [ ] טיפול בשגיאות לפי ARCHITECTURE סעיף 10.

**תוצרים:** ספריית Engine + בדיקות יחידה + CLI לבדיקה.
**בדיקות:** תמונות 1MP / 12MP / 24MP; מסכות קטנות/גדולות/מרובות; מסכה ריקה; קובץ מודל פגום; ביטול באמצע.
**DoD:** אין קריסות על סט הבדיקות; פיקסלים מחוץ למסכה זהים; שימוש בזיכרון מתחת לתקרה שהוגדרה.

- [ ] תצוגת לפני/אחרי.
- [ ] ריצה ברקע עם Progress וביטול.

**תוצרים:** אפליקציה עובדת (גרסת Alpha).
**בדיקות:** תרחישי משתמש ידניים; 20 צעדי Undo/Redo; תגובתיות ה-UI בזמן הרצה.
