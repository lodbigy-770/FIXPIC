## 2026-11-12 – M1.5 (שיחה A): תוצאות OpenVINO ו-3 threads

**שלב:** Milestone 1.5, חלק OpenVINO/3 threads – **בוצע ונותח.** השלב כולו עדיין פתוח.

**סביבה:** i5-6500T (4 ליבות פיזיות), 7.9GB, Windows 11, Python 3.14.3, ORT 1.31.1, OpenVINO 2026.4.1, עומס לפני ההרצה 8.2%. ההתקנים שנמצאו: CPU ו-iGPU (Intel HD Graphics 530). 15 שורות מדידה, בלי שגיאות compile (גם FFT של Big LaMa עבר ב-OpenVINO). הנתונים: `openvino_results.json` (נדחף על ידי המשתמש).

**חציון שניות לקלט 256 / 384 / 512:**

| backend | 256 | 384 | 512 | compile |
|---------|-----|-----|-----|---------|
| ORT t3 | 0.91 | 2.13 | 4.02 | - |
| ORT t4 | 0.84 | 1.97 | 3.90 | - |
| OpenVINO CPU t3 | 0.83 | 1.68 | 3.12 | 5.5–5.8s |
| OpenVINO CPU t4 | 0.69 | 1.45 | 2.73 | 5.4–5.7s |
| OpenVINO iGPU | 0.61 | 1.42 | 2.78 | 13.8–15.5s |

**ממצאים:**
1. **3 threads במקום 4:** ב-ORT עולה 8% / 8% / 3% בלבד; ב-OpenVINO 20% / 16% / 14%. מספיק קטן כדי להשאיר ליבה ל-UI, ולכן 3 מוצע כברירת מחדל.
2. **OpenVINO CPU מהיר מ-ORT** באותו מספר threads: ב-4 threads חיסכון של 18% / 26% / 30% (פי 1.22 / 1.36 / 1.43); ב-3 threads 9% / 21% / 22%. **OpenVINO ב-3 threads שווה ל-ORT ב-4 ב-256, ומהיר ב-15% וב-20% ב-384 וב-512**, תוך שהוא משאיר ליבה פנויה.
3. **נכונות:** ההפרש בתוך המסכה מול ORT הוא עד 0.001 בסקאלה 0–255, כלומר אין שינוי איכות.
4. **עלות compile:** כ-5.5 שניות לכל גודל (כולל קריאת המודל, הכלי מודד את שניהם יחד). זו עלות חד-פעמית לכל גודל בכל הרצה של האפליקציה, ולכן ה-Pipeline חייב לעבוד בגדלים קבועים (256/384/512) ולהתחמם ברקע. **לא נמדד:** צורה דינמית (`--dynamic` לא הורץ) ומטמון על הדיסק (`CACHE_DIR`), שעשויים לצמצם את העלות.
5. **iGPU:** יתרון של 13% בלבד ב-256, שווה ב-384 ואיטי ב-512 במעט (2.78 מול 2.73 של OpenVINO CPU t4); compile של 14–15.5 שניות; שיא זיכרון 2.06GB. המשתמש בחר לא להרחיב אליו, וההחלטה מתועדת. בנוסף נוצר בשורש הריפו `kernel.errors.txt` (פלט שגיאות של מהדר ה-GPU, ככל הנראה מהרצת ה-iGPU); התוצאות תקינות, והקובץ מיותר ואפשר להסיר אותו מהריפו (לא נמחק ללא אישור).
6. **ORT t4 עכשיו מול הרצת `--big`:** 0.84 / 1.97 / 3.90 מול 0.83 / 1.94 / 3.79 קודם, כלומר המדידות עקביות (הפרש עד 3%).
7. **זיכרון (שיא תהליך מצטבר):** ORT עד 1.13GB, OpenVINO CPU עד 1.51GB. מחיר זיכרון נוסף של כ-0.4GB.

**השפעה על התקציב:** אינו משתנה. עם OpenVINO ב-3 threads: אינטראקטיבי (256) כ-0.8 שניות, רגיל (384) כ-1.7 שניות, איכות (512) כ-3.1 שניות, כלומר כ-15–20% מתחת לזמנים שאושרו. אפשר להשאיר את הספים כפי שהם או להקשיח אותם; ההכרעה פתוחה.

**המלצה (לא הוכרעה):** לאמץ OpenVINO CPU כ-backend ראשי ב-3 threads, מאחורי `InpaintModel`, עם ORT כ-fallback אם OpenVINO לא זמין או ה-compile נכשל. שיקולים נגד: תלות נוספת (גודל החבילה לא נמדד), 5.5 שניות compile לכל גודל, 0.4GB זיכרון נוסף, והמדידה רק על מעבד Intel אחד (על מעבדים אחרים לא ידוע). נדרשת הכרעת המשתמש ועדכון ADR (כיום `ARCHITECTURE.md` מציין ONNX Runtime CPU).

**קבצים שהשתנו:** `MODEL_CARD.md` (§6), `ROADMAP.md`, `PROGRESS.md`, `DEVELOPMENT_LOG.md`.

**הבא:** הכרעת המשתמש על OpenVINO; אחר כך `--dynamic` ומטמון, UI Spike, GIL וזמן עלייה, ואריזה על 3.14.
